## Objective

This guide explains how to enable logs forwarding from your OVHcloud Load Balancer to Logs Data Platform (LDP). Once forwarding is enabled, the access logs generated by your TCP, HTTP and HTTPS listeners are ingested into a Logs Data Platform data stream, where you can store, query and visualise them.

**In this guide, you will learn how to:**

- Prepare your Load Balancer by refreshing its configuration so the logging format is up to date.
- Retrieve the target data stream of your Logs Data Platform account.
- Create a log subscription to start forwarding logs.
- Verify the subscription and view the forwarded logs.
- Manage and cancel an existing subscription.

:::warning
The logs of **UDP** listeners are not forwarded. Only TCP, HTTP and HTTPS listener logs are supported.
:::

## Requirements

- An up-and-running [OVHcloud Load Balancer](/guides/network/load-balancer-revamp/what-is-load-balancer).
- A [Logs Data Platform account](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start) with at least one active data stream configured.
- The Logs Data Platform account and the OVHcloud Load Balancer must belong to the same OVHcloud account.
- OVHcloud API credentials (application key, application secret, consumer key). Refer to the [First steps with the OVHcloud API](/guides/manage-and-operate/api/first-steps) guide.
- Access to the <ManagerLink to="/">OVHcloud Control Panel</ManagerLink>.

:::tip
If you are not familiar with Logs Data Platform data stream configuration, create a new stream with the default options (indexing and websocket enabled, long-term storage disabled) for this guide.
:::

## Introduction

OVHcloud Load Balancer is built on [HAProxy](https://en.wikipedia.org/wiki/HAProxy), the open-source component used for load balancing. The access logs forwarded to Logs Data Platform are produced by HAProxy. Logs Data Platform (LDP) is a fully managed log management platform operated by OVHcloud that lets you ingest, store, archive, query and visualise logs through a data stream.

Logs forwarding ingests the logs of an OVHcloud service into an LDP data stream within the same OVHcloud account. You enable it per service. When you enable forwarding for a Load Balancer towards a data stream, a *subscription* is created and attached to that stream for later management.

Enabling forwarding is free of charge. You are charged for your usage of Logs Data Platform according to the standard price plan. For details, refer to the [Logs Data Platform pricing](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start) and the [LDP service page](/links/manage-operate/ldp).

### How forwarding works <a name="how-it-works"></a>

Forwarding is enabled per Load Balancer and per log kind (`tcp` or `http`). Each enablement creates a subscription that links your Load Balancer to a single Logs Data Platform data stream. The following diagram shows the end-to-end flow.

<img className="thumbnail" alt="How forwarding works diagram" src="/images/network/load-balancer-revamp/configure-logs-forwarding/fig-1.svg" loading="lazy" />

| Term | Meaning |
|---|---|
| Data stream | A logical partition of logs in an LDP account. It is the unit used to define retention, archiving, live streaming, access rights and alert policies. |
| Logs forwarding | The feature that ingests Load Balancer logs into an LDP data stream. Enabled per service. |
| Subscription | The object created when forwarding is enabled. It attaches the Load Balancer logs to a given data stream and is used for later management. |
| Log kind | The category of logs to forward: `tcp` or `http`. Retrieved with the log kind API endpoint. |

### Log content reference <a name="log-content"></a>

The fields described below are present in the forwarded logs. The first table applies to all TCP-based listeners (`tcp` and `http` kinds). The second table lists the additional fields present for `http` listeners.

#### Fields for TCP-based listeners (`tcp`, `http`)

| Field name | Description | Type |
|---|---|---|
| `service_name` | The name of the Load Balancer that received the request or connection. | String |
| `date_time` | The timestamp at which the request or connection was made. | Datetime, millisecond resolution (e.g. `25/Mar/2024:14:07:19.536`) |
| `zone` | The OVHcloud region to which the Load Balancer belongs. | String |
| `client_ip` | IP address of the client that initiated the TCP connection. | IP |
| `client_port_int` | TCP port of the client that initiated the TCP connection. | Integer |
| `frontend_name` | Name of the frontend of your Load Balancer. | String |
| `frontend_ip` | IP address of the frontend of your Load Balancer. | IP |
| `frontend_port_int` | TCP port of the frontend of your Load Balancer. | Integer |
| `backend_name` | Name of the NAT source used by the Load Balancer to connect to your backend servers. | String |
| `backend_source_ip` | Source IP address used by the Load Balancer to connect to your backend servers. | IP |
| `backend_source_port_int` | Source port used by the Load Balancer to connect to your backend servers. | Integer |
| `server_ip` | IP address of the backend server connected to your Load Balancer. | IP |
| `server_port_int` | TCP port of the backend server connected to your Load Balancer. | Integer |
| `termination_state` | The session termination indicator: 2 letters for TCP, 4 letters for HTTP. See the [HAProxy documentation](https://docs.haproxy.org/2.6/configuration.html#8.5). | String (e.g. `----`) |
| `bytes_read_int` | Size, in bytes, of the response sent by the Load Balancer to the client. | Integer |
| `bytes_uploaded_int` | Size, in bytes, of the request sent by the client to the Load Balancer. | Integer |
| `time_duration_int` | The duration, in milliseconds, of the TCP session at the time the request was made. | Integer |

#### Additional fields for `http` listeners

| Field name | Description | Type |
|---|---|---|
| `captured_request_headers` | The headers of the HTTP request (e.g. `User-Agent`). | String |
| `http_request` | The resource of the HTTP request (e.g. `/index.html`). | String |
| `http_status_code_int` | The returned HTTP status (e.g. `200`). | Integer |

### Step 1 — Refresh the Load Balancer configuration <a name="step-1"></a>

Before forwarding any logs, refresh the Load Balancer whose logs you want to collect. This applies the current configuration and ensures the logging format is up to date.

You need the `serviceName`, which is the internal name of your Load Balancer. You can find it on the Load Balancer management page in the <ManagerLink to="/">OVHcloud Control Panel</ManagerLink> (<code className="action">Network</code> > <code className="action">Load Balancer</code>), or by listing your services with the API.

<Api version="v1" section="/ipLoadbalancing" method="GET" route="/ipLoadbalancing" />

Then apply the configuration:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | Internal name of your Load Balancer. | `loadbalancer-xxxxxxxxxxxxxxxxxxxx` |

### Step 2 — Retrieve your target data stream <a name="step-2"></a>

Identify the Logs Data Platform data stream that will receive your logs. You need its `streamId` to create the subscription in the next step.

Retrieve the list of streams and the details of a specific stream from your Logs Data Platform account. These calls use the `/dbaas/logs` API section. Enter your LDP service name in the form `ldp-xx-xxxx` as the `serviceName`.

{/* DRAFT: To verify — the /dbaas/logs API endpoints are not in the SOT cache; confirm exact paths and methods before publishing */}

| Action | Endpoint | Method |
|---|---|---|
| List data streams | `/dbaas/logs/{serviceName}/output/graylog/stream` | GET |
| Get data stream details | `/dbaas/logs/{serviceName}/output/graylog/stream/{streamId}` | GET |

You can also retrieve the `streamId` from the Logs Data Platform interface. For details, refer to the [Logs Data Platform quick start](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start) guide.

:::info
Note the `streamId` value (for example `18d602ec-af40-4000-8e59-41ecc8c23f80`). You pass it to the subscription call in Step 3.
:::

### Step 3 — Create the log subscription <a name="step-3"></a>

Create a subscription that links your Load Balancer logs to the target data stream. This is the call that enables forwarding.

First, list the available log kinds for your Load Balancer so you can choose the correct `kind` value:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/log/kind"} />

Then create the subscription:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/log/subscription"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | Internal name of your Load Balancer. | `loadbalancer-xxxxxxxxxxxxxxxxxxxx` |
| `kind` (body) | Yes | The kind of log to forward: `http` or `tcp`. | `http` |
| `streamId` (body) | Yes | The target LDP data stream that will receive the logs. | `18d602ec-af40-4000-8e59-41ecc8c23f80` |

**Example request body:**

```json
{
  "kind": "http",
  "streamId": "18d602ec-af40-4000-8e59-41ecc8c23f80"
}
```

**Example response:**

```json
{
  "operationId": "f550aa1c-89ab-4b1a-81ae-4fba4959966f",
  "serviceName": "ldp-xxxxx"
}
```

The response returns an `operationId`. You use it in the next step to retrieve the resulting `subscriptionId`.

### Step 4 — Verify the subscription <a name="step-4"></a>

Confirm that the subscription was created and forwarding is active.

Once the operation is finished, list the subscriptions of your Load Balancer to retrieve the `subscriptionId`:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/log/subscription"} />

Then get the details of a specific subscription:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/log/subscription/\{subscriptionId\}"} />

**Example response:**

```json
{
  "createdAt": "2026-06-05T13:41:19.713Z",
  "kind": "http",
  "resource": {
    "name": "string",
    "type": "string"
  },
  "serviceName": "loadbalancer-xxxxxxxxxxxxxxxxxxxx",
  "streamId": "18d602ec-af40-4000-8e59-41ecc8c23f80",
  "subscriptionId": "19717204-2e10-4000-8c42-d7b11c9ce680",
  "updatedAt": "2026-06-05T13:41:19.713Z"
}
```

To retrieve the `subscriptionId` directly from the operation, you can also query the operation details with the `/dbaas/logs` section:

{/* DRAFT: To verify — the /dbaas/logs operation endpoint is not in the SOT cache; confirm path and method before publishing */}

| Action | Endpoint | Method |
|---|---|---|
| Get operation details | `/dbaas/logs/{serviceName}/operation/{operationId}` | GET |

| Check | How | Expected result |
|---|---|---|
| Subscription exists | List log subscriptions. | The `subscriptionId` appears in the response. |
| Subscription targets the right stream | Get subscription details. | `streamId` matches your target data stream. |
| Logs are arriving | Open the Graylog web UI for your LDP account. | New Load Balancer entries appear in the data stream. |

### View the forwarded logs <a name="view-logs"></a>

After the logs are ingested into your Logs Data Platform data stream, you can query them and build dashboards through the Graylog web interface.

1. In the <ManagerLink to="/">OVHcloud Control Panel</ManagerLink>, retrieve the LDP username (for example `logs-xxxx`) and its password from your Logs Data Platform account home page. Refer to the [Logs Data Platform quick start](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start) guide.
2. Open the Graylog web UI. The link is available on your account home page or through your access point, depending on your account region (for example, the Gravelines region is `https://gra1.logs.ovh.com/`).
3. Log in to Graylog with your Logs Data Platform username and password.
4. Search through your logs across the data stream. For search syntax, refer to the [Graylog writing search queries](https://go2docs.graylog.org/current/making_sense_of_your_log_data/writing_search_queries.html) documentation.

:::tip
The `Logs` tab on the Load Balancer page in the Control Panel lets you view recent activity for your service. For long-term storage, alerting, real-time WebSocket streaming, OpenSearch Dashboards and Grafana integration, use Logs Data Platform.
:::

### Manage and cancel a subscription <a name="manage"></a>

You can cancel forwarding at any time by deleting the subscription. After deletion, the data stream no longer receives new Load Balancer logs.

:::warning
Deleting a subscription stops new logs from being forwarded. It does not delete the logs already stored before cancellation. Data stored in a log stream is immutable unless you delete the entire stream.
:::

Delete the subscription with the following call:

<Api version="v1" section="/ipLoadbalancing" method="DELETE" route={"/ipLoadbalancing/\{serviceName\}/log/subscription/\{subscriptionId\}"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | Internal name of your Load Balancer. | `loadbalancer-xxxxxxxxxxxxxxxxxxxx` |
| `subscriptionId` | Yes | Identifier of the subscription to delete. | `19717204-2e10-4000-8c42-d7b11c9ce680` |

Logs forwarding subscriptions are managed through the OVHcloud API only. The OVHcloud Terraform provider can manage Load Balancer farms, servers and routes (for example `ovh_iploadbalancing_http_farm`, `ovh_iploadbalancing_tcp_farm`), but it does not provide a resource for log subscriptions, so use the API calls above to create and delete them.

### Limitations <a name="limitations"></a>

This section lists the known constraints of Load Balancer logs forwarding.

| Limitation | Details |
|---|---|
| UDP listeners | Logs of UDP listeners are not forwarded. Only `tcp` and `http` kinds are supported. |
| Same account | The Logs Data Platform account and the Load Balancer must belong to the same OVHcloud account. |
| Control Panel enablement | Enabling forwarding (creating a subscription) is performed through the OVHcloud API. This feature is not yet available in the Control Panel. |
| Immutable history | Cancelling a subscription does not remove logs already stored in the data stream. |

### Troubleshooting <a name="troubleshooting"></a>

This section covers the most common issues when setting up logs forwarding.

| Issue | Possible cause | Solution |
|---|---|---|
| No logs appear in the data stream | The Load Balancer configuration was not refreshed. | Run the refresh call in [Step 1](#step-1) and wait for the operation to complete. |
| No logs appear in the data stream | The subscription targets the wrong `streamId`. | Get the subscription details in [Step 4](#step-4) and confirm `streamId` matches your target stream. |
| Subscription creation fails | The LDP account and the Load Balancer are in different OVHcloud accounts. | Use a data stream that belongs to the same OVHcloud account as the Load Balancer. |
| Only some traffic is logged | UDP listeners are not forwarded. | Expect logs only for `tcp`, `http` and `https` listeners. |
| Cannot find the `serviceName` | Unsure of the internal Load Balancer name. | Retrieve it from the Control Panel or with the `GET /ipLoadbalancing` call in [Step 1](#step-1). |

If the steps above do not resolve the issue:

1. Gather the `operationId`, `subscriptionId`, `serviceName` and `streamId` involved.
2. Contact [OVHcloud support](https://help.ovhcloud.com/) and provide the diagnostic information collected above.
