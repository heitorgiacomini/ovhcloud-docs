## Objective

By default, the OVHcloud Load Balancer acts as a proxy that forwards client traffic to a server farm. It can instead return an HTTP redirection that sends the client to another URL. This is useful for forcing the HTTPS version of a site or migrating a domain name.

**This guide explains how to configure an HTTP redirection on a Load Balancer frontend, using either the OVHcloud Control Panel or the OVHcloud API.**

## Requirements

- An active <ManagerLink to="/">OVHcloud account</ManagerLink>
- Access to the <ManagerLink to="/">OVHcloud Control Panel</ManagerLink>
- An OVHcloud Load Balancer service in your account — see [Order a Load Balancer](/guides/network/load-balancer-revamp/order-load-balancer)
- An existing HTTP or HTTPS frontend — see [Configure frontends](/guides/network/load-balancer-revamp/configure-frontends)

## Introduction

An HTTP redirection is a response in which the Load Balancer returns a `3xx` status code and a `Location` header pointing the client to a new URL, rather than forwarding the request to a backend. A typical response looks like this:

```http
HTTP/1.1 301 Moved Permanently
Location: https://www.example.org/
Content-Type: text/html
Content-Length: 174
```

You configure the redirection on a frontend through its redirect location. The value must follow the format `<scheme>://<net_loc>/<path>;<params>?<query>#<fragment>`. You can define only one redirection per frontend.

> [!INFO]
> When a frontend is configured with a redirection, it does not forward traffic to a server farm. A default farm is therefore not required on that frontend.

## Instructions

You can configure a redirection on a new frontend during creation, or on an existing frontend. Both the Control Panel and the OVHcloud API support either case.

<Tabs>
<Tab label="Control Panel">

1. Log in to the <ManagerLink to="/">OVHcloud Control Panel</ManagerLink> and open the <code className="action">Network</code> section, then <code className="action">Load Balancer</code>.
2. Select your Load Balancer service, then open the <code className="action">Frontends</code> tab.
3. To create a new frontend, click <code className="action">Create frontend</code>. To modify an existing one, open the actions menu to the right of the frontend and select <code className="action">Edit</code>.
4. Select the `HTTP` or `HTTPS` protocol for the frontend. A redirection can only be set on HTTP or HTTPS frontends.
5. Complete the standard frontend settings. You do not need to set a default farm, because traffic is redirected rather than forwarded.
6. Under `Default route`, select the <code className="action">Redirect to URL</code> option and enter the destination URL.

7. Confirm the frontend by clicking <code className="action">Create Frontend</code> or <code className="action">Save changes</code>, depending on whether you are creating or modifying.

Apply the pending configuration by clicking <code className="action">Apply changes</code> so the redirection becomes active.

For details on applying changes, see the [Manage your Load Balancer via the Control Panel](/guides/network/load-balancer-revamp/manage-via-control-panel) guide.

</Tab>
<Tab label="OVHcloud API">

In the OVHcloud API, you set the redirection through the `redirectLocation` property of an HTTP frontend. Configure it on a new or an existing frontend, then apply the changes.

**Create a frontend with a redirection**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/http/frontend"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | Identifier of your Load Balancer service. | `loadbalancer-xxxxxxxx` |
| `port` (body) | Yes | Listening port of the frontend. | `80` |
| `zone` (body) | Yes | Deployment zone of the frontend. | `all` |
| `redirectLocation` (body) | No | Destination URL of the HTTP redirection. | `https://www.example.org/` |

**Modify an existing frontend**

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/http/frontend/\{frontendId\}"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | Identifier of your Load Balancer service. | `loadbalancer-xxxxxxxx` |
| `frontendId` | Yes | Identifier of the frontend to modify. | `12345` |
| `redirectLocation` (body) | No | Destination URL of the HTTP redirection. | `https://www.example.org/` |

**Apply the configuration**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | Identifier of your Load Balancer service. | `loadbalancer-xxxxxxxx` |

The redirection becomes active once the configuration is applied.

</Tab>
<Tab label="Terraform">

The OVHcloud Terraform provider configures redirections through the `redirect_location` argument of the `ovh_iploadbalancing_http_frontend` resource. After changing a frontend, apply the pending configuration with the `ovh_iploadbalancing_refresh` resource.

The provider also covers related Load Balancer objects such as the service (`ovh_iploadbalancing`), server farms (`ovh_iploadbalancing_http_farm`), and HTTP routes (`ovh_iploadbalancing_http_route`, `ovh_iploadbalancing_http_route_rule`).

</Tab>
