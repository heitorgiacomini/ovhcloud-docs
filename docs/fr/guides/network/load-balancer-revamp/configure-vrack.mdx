## Objectif

Le Load Balancer OVHcloud peut joindre vos serveurs backend via un réseau privé vRack plutôt que par l'internet public. Cela isole le trafic des backends du réseau public et évite d'avoir à exposer vos serveurs sur des adresses IP publiques.

Ce guide vous accompagne tout au long du processus : attacher le Load Balancer à un vRack, déclarer un réseau privé (sous-réseau et plage NAT) afin que le Load Balancer connaisse la topologie de votre vRack, et créer des fermes de serveurs qui joignent les backends via leurs adresses IP privées.

**Ce guide explique comment configurer le vRack sur votre Load Balancer OVHcloud afin de joindre les serveurs backend via des adresses IP privées.**

**Dans ce guide, vous apprendrez à :**

- Attacher un service Load Balancer à un vRack.
- Configurer un réseau privé (sous-réseau et plage d'IP NAT) sur le Load Balancer.
- Créer une ferme de serveurs qui joint les backends via leurs adresses IP privées.

:::warning
Une fois qu'un service Load Balancer est relié à un vRack, ses fermes de serveurs ne peuvent plus joindre vos serveurs via leurs adresses IP publiques. À partir de ce moment, le Load Balancer ne contacte vos serveurs que par la plage d'IP privées que vous lui dédiez à l'intérieur du vRack. Planifiez la bascule en conséquence afin d'éviter toute interruption de la connectivité vers les backends.
:::

## Prérequis

- Un compte OVHcloud actif
- Un accès à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>
- Un Load Balancer OVHcloud (consultez le guide [Commander un Load Balancer](/guides/network/load-balancer-revamp/order-load-balancer))
- Un [vRack](https://www.ovhcloud.com/fr/network/vrack/) existant dont la topologie réseau est déjà définie
- Les serveurs backend qui recevront le trafic déjà connectés au même vRack, chacun joignable sur une adresse IP privée
- Des identifiants de l'API OVHcloud pour les étapes via l'API. Consultez le guide [Premiers pas avec l'API OVHcloud](/guides/manage-and-operate/api/first-steps).

## Introduction

Le vRack est un réseau privé de niveau 2 qui interconnecte les services OVHcloud compatibles sans transiter par l'internet public. Lorsque le Load Balancer est attaché à un vRack, vous lui attribuez une plage dédiée d'adresses IP privées (la plage d'IP NAT) à l'intérieur de l'un de vos sous-réseaux vRack. Le Load Balancer utilise cette plage comme source de tout le trafic envoyé à vos serveurs backend ; ainsi, les serveurs ne voient que des adresses sources privées et n'ont pas besoin d'une exposition publique.

Vous attachez le vRack via l'API OVHcloud et vous configurez les réseaux privés depuis l'onglet <code className="action">vRack</code> de l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>. Ce même onglet vous permet de consulter et de gérer les sous-réseaux privés une fois qu'ils existent.

### Vue d'ensemble <a name="overview"></a>

Trois éléments de configuration relient le Load Balancer à vos backends privés. Premièrement, attachez le service Load Balancer au vRack. Deuxièmement, déclarez un réseau privé sur le Load Balancer depuis l'onglet <code className="action">vRack</code> : cela lui indique dans quel sous-réseau résident vos serveurs et quelle plage d'IP NAT il peut utiliser comme source du trafic vers les backends. Troisièmement, liez chaque ferme de serveurs à ce réseau privé afin que ses serveurs soient adressés par leurs IP privées.

Le schéma ci-dessous illustre le flux de trafic résultant.

<img className="thumbnail" alt="Vue d'ensemble — schéma" src="/images/network/load-balancer-revamp/configure-vrack/fig-1.fr.svg" loading="lazy" />

Les principaux paramètres d'un réseau privé sont résumés ci-dessous.

| Paramètre | Description | Exemple |
|---|---|---|
| Sous-réseau (CIDR) | La plage CIDR du sous-réseau vRack où résident vos serveurs. | `192.168.0.0/16` |
| NAT IP | La plage CIDR que le Load Balancer utilise comme source du trafic vers les backends. Elle doit être contenue dans le sous-réseau et dédiée au Load Balancer. | `192.168.100.0/24` |
| `vrackNetworkId` | L'identifiant du réseau privé une fois créé. Requis pour lier une ferme au réseau. | `2001` |

:::info
La plage d'IP NAT doit être contenue dans la plage du sous-réseau, et elle ne doit pas chevaucher des adresses déjà attribuées à vos serveurs ou à d'autres services dans le vRack.
:::

### Étape 1 — Attacher le Load Balancer à un vRack <a name="step-1"></a>

Cette étape relie le service Load Balancer à votre vRack via l'API OVHcloud.

Vérifiez d'abord que votre service Load Balancer est éligible pour rejoindre le vRack. Le `serviceName` utilisé par les endpoints du vRack est le nom de votre vRack (par exemple, `pn-1234`), et non le nom du Load Balancer.

<Api version="v1" section="/vrack" method="GET" route={"/vrack/\{serviceName\}/eligibleServices"} />

Les services Load Balancer éligibles sont listés sous l'index `ipLoadbalancing` de la réponse. Vous pouvez également consulter l'éligibilité d'un service Load Balancer précis via l'attribut `vrackEligibility` renvoyé par l'appel suivant (ici, `serviceName` est le nom du service Load Balancer) :

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}"} />

Une fois l'éligibilité confirmée, attachez le Load Balancer au vRack :

<Api version="v1" section="/vrack" method="POST" route={"/vrack/\{serviceName\}/ipLoadbalancing"} />

Vous pouvez également attacher un vRack depuis l'onglet <code className="action">vRack</code> de l'<ManagerLink to="/">espace client OVHcloud</ManagerLink> à l'aide du bouton <code className="action">Attacher un vRack</code>, puis le retirer ultérieurement avec <code className="action">Détacher</code>.

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` (path) | Oui | Le nom de votre vRack. | `pn-1234` |
| `ipLoadbalancing` (body) | Oui | Le service Load Balancer à attacher. | `loadbalancer-a1b2c3...` |

### Étape 2 — Configurer un réseau privé <a name="step-2"></a>

Pour que le Load Balancer puisse communiquer avec vos backends, il doit connaître la topologie réseau à l'intérieur de votre vRack et posséder une plage dédiée d'adresses IP privées au sein de celle-ci. Cette plage est la seule source de trafic que le Load Balancer utilise pour contacter vos serveurs.

Rendez-vous dans l'<ManagerLink to="/">espace client OVHcloud</ManagerLink> et ouvrez votre service Load Balancer. Sélectionnez l'onglet <code className="action">vRack</code>, puis cliquez sur <code className="action">Ajouter un réseau privé</code> et renseignez les champs suivants :

- <code className="action">Sous-réseau (CIDR)</code> : la plage CIDR du sous-réseau vRack où résident vos serveurs (par exemple, `192.168.0.0/16`).
- <code className="action">NAT IP</code> : la plage CIDR dédiée au Load Balancer, contenue dans le sous-réseau (par exemple, `192.168.100.0/24`).

{/* DRAFT: À capturer — l'onglet vRack du Load Balancer avec le formulaire Ajouter un réseau privé ouvert */}

Vous pouvez consulter les sous-réseaux d'IP NAT déjà déclarés sur le service via l'API OVHcloud :

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/natIp"} />

:::warning
La plage d'IP NAT doit être contenue dans la plage du sous-réseau. Choisissez une plage qui est dédiée au Load Balancer et qui n'est utilisée par aucun serveur ni autre service dans le vRack.
:::

Une fois le réseau privé créé, notez son `vrackNetworkId`. Vous aurez besoin de cet identifiant pour lier une ferme de serveurs au réseau à l'étape suivante.

### Étape 3 — Créer une ferme liée au réseau privé <a name="step-3"></a>

Créez votre ferme de serveurs et liez-la au réseau privé en fournissant le `vrackNetworkId` obtenu à l'étape précédente. Hormis ce champ, vous configurez la ferme exactement comme vous le feriez pour une ferme publique.

<Tabs>
<Tab label="Espace client">

Rendez-vous dans l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>, ouvrez votre service Load Balancer et sélectionnez l'onglet <code className="action">Fermes</code>. Cliquez sur <code className="action">Créer une ferme</code> et configurez la ferme comme d'habitude, en sélectionnant le réseau privé que vous avez créé afin que les serveurs backend soient adressés par leur IP privée.

{/* DRAFT: À capturer — le formulaire de création de ferme de serveurs montrant la sélection du réseau privé / sous-réseau */}

Lorsque vous ajoutez des serveurs à la ferme, saisissez leurs adresses IP privées à l'intérieur du vRack. Cliquez sur <code className="action">Ajouter un serveur</code> pour chaque backend.

</Tab>
<Tab label="API OVHcloud">

Créez une ferme HTTP et fournissez le champ `vrackNetworkId` :

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/http/farm"} />

Pour une ferme TCP, utilisez l'endpoint équivalent :

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` (path) | Oui | Le nom du service Load Balancer. | `loadbalancer-a1b2c3...` |
| `zone` (body) | Oui | La zone dans laquelle la ferme est déployée. | `gra` |
| `port` (body) | Non | Le port vers lequel la ferme transfère le trafic sur les backends. | `80` |
| `vrackNetworkId` (body) | Oui (pour les fermes vRack) | L'identifiant du réseau privé créé à l'étape 2. | `2001` |

Après avoir créé la ferme, ajoutez vos serveurs backend à l'aide de leurs adresses IP privées. Pour la configuration complète des fermes et des serveurs, consultez le guide [Configurer les fermes de serveurs](/guides/network/load-balancer-revamp/configure-server-farms).

</Tab>
<Tab label="Terraform">

Avec le provider Terraform OVHcloud, le réseau privé est déclaré avec la ressource `ovh_iploadbalancing_vrack_network`, et la ferme y est liée avec `ovh_iploadbalancing_http_farm` (ou `ovh_iploadbalancing_tcp_farm`), en référençant l'identifiant de réseau exporté par la ressource `ovh_iploadbalancing_vrack_network`. Les serveurs backend sont ajoutés avec `ovh_iploadbalancing_http_farm_server` (ou `ovh_iploadbalancing_tcp_farm_server`) en utilisant leurs adresses IP privées.

:::info
Il n'existe pas de ressource Terraform pour appliquer la configuration. Après vos modifications Terraform, appliquez la configuration en attente via l'API OVHcloud ou l'espace client, comme décrit ci-dessous.
:::

</Tab>
</Tabs>

Appliquez la configuration pour que les changements prennent effet, soit via l'API OVHcloud, soit à l'aide du bouton <code className="action">Appliquer les modifications</code> dans l'espace client :

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />

:::tip
Les modifications de configuration sur le Load Balancer sont mises en attente jusqu'à ce que vous les appliquiez. Consultez les modifications en attente avec `GET /ipLoadbalancing/{serviceName}/pendingChanges` avant de les appliquer.
:::

### Vérification <a name="verification"></a>

Après avoir appliqué la configuration, vérifiez que chaque partie de l'installation est en place.

| Vérification | Comment | Résultat attendu |
|---|---|---|
| Le Load Balancer est attaché au vRack | `GET /ipLoadbalancing/{serviceName}` et lecture du statut d'attachement au vRack / `vrackEligibility` | Le service est signalé comme attaché au vRack |
| Le réseau privé existe | Listez les sous-réseaux d'IP NAT déclarés avec `GET /ipLoadbalancing/{serviceName}/natIp` | Le sous-réseau et la plage d'IP NAT que vous avez définis sont renvoyés |
| La ferme est liée au réseau privé | `GET /ipLoadbalancing/{serviceName}/http/farm` (ou `/tcp/farm`) et examen de la ferme | La ferme affiche le `vrackNetworkId` attendu |
| Les backends sont joignables via des IP privées | Listez les serveurs de la ferme et vérifiez leur état | Les serveurs sont signalés comme joignables via leurs adresses IP privées |

### Limitations <a name="limitations"></a>

| Limitation | Détails |
|---|---|
| Aucun accès public aux backends après l'attachement | Une fois le Load Balancer attaché à un vRack, ses fermes ne peuvent joindre les serveurs que via la plage d'IP NAT privée. Les IP publiques des backends ne sont plus utilisées. |
| Contenance de la plage d'IP NAT | La plage d'IP NAT doit être contenue dans le sous-réseau déclaré et ne doit pas chevaucher des adresses vRack existantes. |

### Résolution des problèmes <a name="troubleshooting"></a>

Cette section liste les problèmes les plus fréquents lors de la configuration d'un vRack sur le Load Balancer.

| Problème | Cause possible | Solution |
|---|---|---|
| Backends injoignables après l'attachement au vRack | Les fermes référencent encore des adresses IP publiques | Mettez à jour chaque serveur de ferme pour utiliser son adresse IP privée à l'intérieur du vRack, puis appliquez la configuration. |
| Création du réseau privé refusée | Plage d'IP NAT non contenue dans le sous-réseau, ou plage trop petite | Choisissez une plage d'IP NAT contenue dans le sous-réseau et dédiée au Load Balancer. |
| Les modifications de configuration ne sont pas actives | Les modifications en attente n'ont pas été appliquées | Appliquez la configuration avec `POST /ipLoadbalancing/{serviceName}/refresh`. |
| Impossible de lier la ferme au réseau privé | `vrackNetworkId` manquant ou incorrect | Récupérez le bon `vrackNetworkId` du réseau privé créé et fournissez-le lors de la création ou de la modification de la ferme. |

Pour un diagnostic plus large, consultez le guide [Résolution des problèmes](/guides/network/load-balancer-revamp/troubleshooting).
