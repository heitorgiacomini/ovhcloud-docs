## Objectif

Par défaut, l'OVHcloud Load Balancer agit comme un proxy qui transmet le trafic des clients vers une ferme de serveurs. Il peut, à la place, renvoyer une redirection HTTP qui dirige le client vers une autre URL. Cela s'avère utile pour forcer la version HTTPS d'un site ou pour migrer un nom de domaine.

**Ce guide explique comment configurer une redirection HTTP sur un frontend de Load Balancer, à l'aide de l'espace client OVHcloud ou de l'API OVHcloud.**

## Prérequis

- Un <ManagerLink to="/">compte OVHcloud</ManagerLink> actif
- Accéder à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>
- Un service OVHcloud Load Balancer sur votre compte — voir [Commander un Load Balancer](/guides/network/load-balancer-revamp/order-load-balancer)
- Un frontend HTTP ou HTTPS existant — voir [Configurer les frontends](/guides/network/load-balancer-revamp/configure-frontends)

## Introduction

Une redirection HTTP est une réponse dans laquelle le Load Balancer renvoie un code de statut `3xx` ainsi qu'un en-tête `Location` qui dirige le client vers une nouvelle URL, au lieu de transmettre la requête à un backend. Une réponse typique ressemble à ceci :

```http
HTTP/1.1 301 Moved Permanently
Location: https://www.example.org/
Content-Type: text/html
Content-Length: 174
```

Vous configurez la redirection sur un frontend par l'intermédiaire de son emplacement de redirection. La valeur doit respecter le format `<scheme>://<net_loc>/<path>;<params>?<query>#<fragment>`. Vous ne pouvez définir qu'une seule redirection par frontend.

> [!INFO]
> Lorsqu'un frontend est configuré avec une redirection, il ne transmet pas le trafic à une ferme de serveurs. Une ferme par défaut n'est donc pas requise sur ce frontend.

## En pratique

Vous pouvez configurer une redirection sur un nouveau frontend lors de sa création, ou sur un frontend existant. L'espace client comme l'API OVHcloud prennent en charge les deux cas.

<Tabs>
<Tab label="Espace client">

1. Connectez-vous à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink> et ouvrez la section `Réseau`, puis `Load Balancer`.
2. Sélectionnez votre service Load Balancer, puis ouvrez l'onglet `Frontends`.
3. Pour créer un nouveau frontend, cliquez sur `Créer un frontend`. Pour modifier un frontend existant, ouvrez le menu d'actions situé à droite du frontend et sélectionnez `Modifier`.
4. Sélectionnez le protocole `HTTP` ou `HTTPS` pour le frontend. Une redirection ne peut être définie que sur des frontends HTTP ou HTTPS.
5. Renseignez les paramètres standard du frontend. Vous n'avez pas besoin de définir une ferme par défaut, car le trafic est redirigé plutôt que transmis.
6. Dans les paramètres avancés, saisissez l'URL de destination dans le champ d'emplacement de redirection. {/* DRAFT: À vérifier — confirmer le libellé exact du champ d'emplacement de redirection dans l'éditeur de frontend du nouveau Manager */}

7. Validez le frontend en cliquant sur `Créer un frontend` ou `Enregistrer les modifications`, selon que vous créez ou modifiez le frontend.

Appliquez la configuration en attente en cliquant sur `Appliquer les modifications` afin que la redirection devienne active.

<Tab label="API OVHcloud">

Dans l'API OVHcloud, vous définissez la redirection via la propriété `redirectLocation` d'un frontend HTTP. Configurez-la sur un frontend nouveau ou existant, puis appliquez les modifications.

**Créer un frontend avec une redirection**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/http/frontend"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Identifiant de votre service Load Balancer. | `loadbalancer-xxxxxxxx` |
| `port` (body) | Oui | Port d'écoute du frontend. | `80` |
| `zone` (body) | Oui | Zone de déploiement du frontend. | `all` |
| `redirectLocation` (body) | Non | URL de destination de la redirection HTTP. | `https://www.example.org/` |

**Modifier un frontend existant**

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/http/frontend/\{frontendId\}"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Identifiant de votre service Load Balancer. | `loadbalancer-xxxxxxxx` |
| `frontendId` | Oui | Identifiant du frontend à modifier. | `12345` |
| `redirectLocation` (body) | Non | URL de destination de la redirection HTTP. | `https://www.example.org/` |

**Appliquer la configuration**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Identifiant de votre service Load Balancer. | `loadbalancer-xxxxxxxx` |

La redirection devient active une fois la configuration appliquée.

</Tab>
<Tab label="Terraform">

Le provider Terraform OVHcloud n'expose pas de ressource pour les frontends HTTP ni pour l'application des modifications de configuration. Les redirections, définies via la propriété `redirectLocation` d'un frontend, doivent donc être configurées via l'API OVHcloud ou l'espace client.

Le provider couvre en revanche les objets Load Balancer associés, tels que le service (`ovh_iploadbalancing`), les fermes de serveurs (`ovh_iploadbalancing_http_farm`) et les routes HTTP (`ovh_iploadbalancing_http_route`, `ovh_iploadbalancing_http_route_rule`). Pour les redirections en particulier, utilisez les onglets API OVHcloud ou Espace client ci-dessus.

</Tab>
