## Objectif

Par défaut, l'OVHcloud Load Balancer agit comme un proxy qui transmet le trafic des clients vers une ferme de serveurs. Il peut aussi, à la place, renvoyer une redirection HTTP qui dirige le client vers une autre URL. C'est utile pour forcer la version HTTPS d'un site ou pour migrer un nom de domaine.

**Ce guide explique comment configurer une redirection HTTP sur un frontend de Load Balancer, à l'aide de l'espace client OVHcloud ou de l'API OVHcloud.**

## Prérequis

- Un <ManagerLink to="/">compte OVHcloud</ManagerLink> actif
- Un accès à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>
- Un service OVHcloud Load Balancer sur votre compte — voir [Commander un Load Balancer](/guides/network/load-balancer-revamp/order-load-balancer)
- Un frontend HTTP ou HTTPS existant — voir [Configurer les frontends](/guides/network/load-balancer-revamp/configure-frontends)

## Introduction

Une redirection HTTP est une réponse dans laquelle le Load Balancer renvoie un code de statut `3xx` ainsi qu'un en-tête `Location` qui dirige le client vers une nouvelle URL, au lieu de transmettre la requête à un backend. Une réponse typique ressemble à ceci :

```http
HTTP/1.1 301 Moved Permanently
Location: https://www.example.org/
Content-Type: text/html
Content-Length: 174
```

La redirection se configure sur un frontend via son emplacement de redirection. La valeur doit respecter le format `<scheme>://<net_loc>/<path>;<params>?<query>#<fragment>`. Vous ne pouvez définir qu'une seule redirection par frontend.

> [!INFO]
> Lorsqu'un frontend est configuré avec une redirection, il ne transmet pas le trafic à une ferme de serveurs. Une ferme par défaut n'est donc pas requise sur ce frontend.

## En pratique

Vous pouvez configurer une redirection sur un nouveau frontend lors de sa création, ou sur un frontend existant. L'espace client comme l'API OVHcloud prennent en charge les deux cas.

<Tabs>
<Tab label="Espace client">

1. Connectez-vous à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink> et ouvrez la section <code className="action">Réseau</code>, puis <code className="action">Load Balancer</code>.
2. Sélectionnez votre service Load Balancer, puis ouvrez l'onglet <code className="action">Frontends</code>.
3. Pour créer un nouveau frontend, cliquez sur <code className="action">Créer un frontend</code>. Pour modifier un frontend existant, ouvrez le menu d'actions situé à droite du frontend et sélectionnez <code className="action">Modifier</code>.
4. Sélectionnez le protocole `HTTP` ou `HTTPS` pour le frontend. Une redirection ne peut être définie que sur des frontends HTTP ou HTTPS.
5. Renseignez les paramètres standard du frontend. Vous n'avez pas besoin de définir une ferme par défaut, car le trafic est redirigé plutôt que transmis.
6. Dans les paramètres avancés, saisissez l'URL de destination dans le champ d'emplacement de redirection.

7. Validez le frontend en cliquant sur <code className="action">Créer le frontend</code> ou <code className="action">Enregistrer les modifications</code>, selon que vous créez ou modifiez le frontend.

Appliquez la configuration en attente en cliquant sur <code className="action">Appliquer les modifications</code> afin que la redirection devienne active.

Pour en savoir plus sur l'application des modifications, consultez le guide [Gérer votre Load Balancer depuis l'espace client](/guides/network/load-balancer-revamp/manage-via-control-panel).

</Tab>
<Tab label="API OVHcloud">

Dans l'API OVHcloud, la redirection se définit via la propriété `redirectLocation` d'un frontend HTTP. Configurez-la sur un frontend nouveau ou existant, puis appliquez les modifications.

**Créer un frontend avec une redirection**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/http/frontend"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Identifiant de votre service Load Balancer. | `loadbalancer-xxxxxxxx` |
| `port` (body) | Oui | Port d'écoute du frontend. | `80` |
| `zone` (body) | Oui | Zone de déploiement du frontend. | `all` |
| `redirectLocation` (body) | Non | URL de destination de la redirection HTTP. | `https://www.example.org/` |

**Modifier un frontend existant**

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/http/frontend/\{frontendId\}"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Identifiant de votre service Load Balancer. | `loadbalancer-xxxxxxxx` |
| `frontendId` | Oui | Identifiant du frontend à modifier. | `12345` |
| `redirectLocation` (body) | Non | URL de destination de la redirection HTTP. | `https://www.example.org/` |

**Appliquer la configuration**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Identifiant de votre service Load Balancer. | `loadbalancer-xxxxxxxx` |

La redirection devient active une fois la configuration appliquée.

</Tab>
<Tab label="Terraform">

Le provider Terraform OVHcloud configure les redirections via l'argument `redirect_location` de la ressource `ovh_iploadbalancing_http_frontend`. Après avoir modifié un frontend, appliquez la configuration en attente à l'aide de la ressource `ovh_iploadbalancing_refresh`.

Le provider couvre également les objets Load Balancer associés, tels que le service (`ovh_iploadbalancing`), les fermes de serveurs (`ovh_iploadbalancing_http_farm`) et les routes HTTP (`ovh_iploadbalancing_http_route`, `ovh_iploadbalancing_http_route_rule`).

</Tab>
