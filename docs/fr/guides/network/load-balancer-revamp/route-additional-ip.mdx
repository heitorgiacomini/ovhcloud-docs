## Objectif

Une Additional IP est une adresse IP que vous pouvez basculer d'un service OVHcloud à un autre. La router vers le Load Balancer OVHcloud déplace le trafic existant vers le Load Balancer sans changer votre adresse IP publique et sans attendre la propagation DNS.

**Ce guide explique comment router une Additional IP vers le Load Balancer OVHcloud, soit pour l'ensemble du service, soit pour un seul frontend.**

## Prérequis

- Un [compte OVHcloud](/links/manager) actif
- Avoir accès à l'[espace client OVHcloud](/links/manager)
- Un Load Balancer OVHcloud configuré — consultez [Commander un Load Balancer](/guides/network/load-balancer-revamp/order-load-balancer)
- Une [Additional IP](/links/network/additional-ip)
- Des identifiants d'API, si vous routez l'IP via l'API OVHcloud — consultez [Prérequis et limitations](/guides/network/load-balancer-revamp/prerequisites-and-limitations)

## Introduction

Vous pouvez router une Additional IP vers le Load Balancer OVHcloud de deux manières :

- La router vers l'**ensemble du service Load Balancer**, ce qui la rend disponible pour tous les frontends.
- La router vers un **seul frontend**, de sorte qu'elle donne accès uniquement au service exposé par ce frontend. Vos autres frontends restent accessibles via l'adresse IP principale du Load Balancer.

Choisissez la portée qui correspond à votre migration : une IP à l'échelle du service pour remplacer une à une une adresse IP publique existante, ou une IP dédiée lorsque vous souhaitez qu'un frontend réponde sur sa propre adresse.

> [!INFO]
> Après avoir modifié les Additional IPs associées au Load Balancer, vous devez appliquer la configuration. Pour que l'actualisation réussisse, les conditions suivantes doivent être réunies :
>
> - **Configuration du vRack :** si le Load Balancer se trouve dans un vRack, toutes les fermes de serveurs doivent également se trouver dans le vRack et le Load Balancer doit avoir son VLAN défini. Sinon, aucune ferme ne doit se trouver dans un vRack.
> - **Validité des frontends :** au moins un frontend doit exister, et tous les frontends doivent être valides (activés ou désactivés). Chacun doit disposer d'une route valide avec des règles de routage, d'une redirection ou d'une ferme par défaut.
> - **État de la configuration :** le Load Balancer ne doit pas déjà être en cours d'une autre actualisation. Un Load Balancer ne peut pas être actualisé plus d'une fois à la fois.

## En pratique

### Router une Additional IP vers l'ensemble du Load Balancer

Cette portée rend l'Additional IP disponible pour tous les frontends du Load Balancer. Routez l'IP via l'API OVHcloud, puis vérifiez l'association.

Commencez par déplacer l'Additional IP vers le service Load Balancer :

<Api version="v1" section="/ip" method="POST" route={"/ip/\{ip\}/move"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `ip` | Oui | L'Additional IP à déplacer, en notation CIDR. | `203.0.113.42/32` |
| `to` (corps) | Oui | Le nom de service du Load Balancer cible. | `loadbalancer-a1b2c3d4` |

> [!INFO]
> L'endpoint `/ip/{ip}/move` fait partie de la section d'API `/ip`. Confirmez les paramètres exacts dans la [console API OVHcloud](/links/api) avant d'exécuter l'appel. [UNVERIFIED: /ip/\{ip\}/move - endpoint not present in the SOT cache, confirm path and body]

Listez ensuite les Additional IPs déjà routées vers votre Load Balancer afin de confirmer l'association :

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/failover"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Le nom de service de votre Load Balancer. | `loadbalancer-a1b2c3d4` |

Une fois l'association confirmée, appliquez la configuration comme décrit dans [Appliquer la configuration](#apply-the-configuration).

### Router une Additional IP dédiée vers un seul frontend

Cette portée rattache l'Additional IP à un seul frontend. L'IP donne alors accès exclusivement au service exposé par ce frontend, tandis que vos autres frontends restent accessibles via l'adresse IP principale du Load Balancer. Configurez une IP dédiée depuis l'espace client ou l'API OVHcloud.

<Tabs>
<Tab label="Espace client">

1. Connectez-vous à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink>.
2. Accédez à **Réseau** > **Load Balancer**.
3. Sélectionnez le Load Balancer que vous souhaitez modifier, puis ouvrez l'onglet `Frontends & routage`.
4. Cliquez sur `Créer un frontend` pour ajouter un nouveau frontend, ou sélectionnez un frontend existant et modifiez-le.
5. Dans les paramètres avancés du frontend, sélectionnez les Additional IPs que vous souhaitez lui associer.

{/* DRAFT: À capturer - les paramètres avancés de l'éditeur de frontends affichant la sélection de l'Additional IP */}

6. Enregistrez le frontend. Le libellé du bouton est `Créer le frontend` pour un nouveau frontend ou `Modifier le frontend` pour un frontend existant.

> [!INFO]
> Le champ des paramètres avancés utilisé pour sélectionner les Additional IPs n'est pas présent dans le cache SOT. [UNVERIFIED: advanced settings dedicated-IP field label - confirm against the New Manager]

Une fois le frontend enregistré, appliquez la configuration comme décrit dans [Appliquer la configuration](#apply-the-configuration).

</Tab>
<Tab label="API OVHcloud">

Définissez une ou plusieurs Additional IPs dédiées lorsque vous créez un frontend.

- Protocole HTTP :

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/http/frontend"} />

- Protocole TCP :

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend"} />

Ou mettez à jour un frontend existant pour y rattacher les Additional IPs dédiées.

- Protocole HTTP :

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/http/frontend/\{frontendId\}"} />

- Protocole TCP :

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend/\{frontendId\}"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Le nom de service de votre Load Balancer. | `loadbalancer-a1b2c3d4` |
| `frontendId` | Oui | L'identifiant numérique du frontend (appels de mise à jour uniquement). | `42` |
| `dedicatedIpfo` (corps) | Oui | La liste des Additional IPs dédiées à rattacher au frontend. | `["203.0.113.42"]` |

> [!INFO]
> Une variante de frontend UDP existe dans l'espace client mais n'est pas présente dans le cache SOT. [UNVERIFIED: /ipLoadbalancing/\{serviceName\}/udp/frontend - confirm the UDP frontend endpoints in the API console]

Une fois l'appel réussi, appliquez la configuration comme décrit dans [Appliquer la configuration](#apply-the-configuration).

</Tab>
</Tabs>

### Appliquer la configuration

<a name="apply-the-configuration"></a>

Les modifications apportées aux Additional IPs restent en attente jusqu'à ce que vous appliquiez la configuration du Load Balancer. Vous pouvez l'appliquer depuis l'espace client de deux manières :

- Depuis l'onglet `Général`, cliquez sur le bouton `...` à côté de votre Load Balancer et sélectionnez `Appliquer les modifications`.
- Depuis le bandeau de rappel qui vous signale que la configuration n'a pas été appliquée, cliquez sur `Appliquer les modifications`.

{/* DRAFT: À capturer - l'action Appliquer les modifications dans l'onglet Général */}

> [!INFO]
> Le libellé de l'action `Appliquer les modifications` et le bandeau de rappel ne sont pas présents dans le cache SOT. [UNVERIFIED: Apply configuration label - confirm against the New Manager]

> [!WARNING]
> La configuration n'est pas active tant qu'elle n'est pas appliquée. Si les conditions de l'introduction ne sont pas réunies, l'actualisation échoue et la configuration précédente reste en place.
